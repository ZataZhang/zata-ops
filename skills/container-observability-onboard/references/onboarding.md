# 接入契约与验证

## 参数来源

以下是可复用的命名，不是对所有平台的固定协议。填入前应检查平台实际配置：

| 参数 | 内容 |
| --- | --- |
| `NODE_NAME` | 稳定、唯一的服务器标签，不随容器重建变化 |
| `LOKI_ENDPOINT` | Vector Loki sink 所需的基础地址；具体 push 路径按 sink 与网关配置核对 |
| `METRICS_ENDPOINT` | remote write 的完整地址，仅在需要指标时配置 |
| `INGEST_USER` | 平台分配的写入身份 |
| `INGEST_PASSWORD` | 对应写入凭据，不是 Grafana 管理员密码 |

非密钥项在 env 示例中用注释形式展示；密码保留可见空字段。不要把日志平台的接入配置混入业务应用 env。示例不包含真实 IP、域名或密码。

## 接入前分层检查

1. **目标与范围**：列出实际容器、Compose 项目与服务；确认复用还是新增采集器。读取有限日志时尽量只判断是否有输出，避免泄漏正文。
2. **网络**：从应用服务器检查 DNS 和 TLS 入口，而非只在监控服务器通过 loopback 验证。云防火墙与宿主机防火墙是两层；HTTPS 可达不代表写入路径可达。
3. **认证**：未带凭据的受保护写入路径应拒绝访问；有效凭据需通过真实写入验证。401 与网络超时不是同类故障，不能通过重置密码修复网络。
4. **资源**：为采集器选择适合该机器的限额及有限磁盘缓冲。保留中心日志不会自动清理 Docker 本地日志；不要为设置轮转而未经授权重建所有应用容器。
5. **版本**：用实际镜像运行配置校验。Vector 某些版本默认禁用环境变量替换；只有配置来源可信时才按该版本官方说明显式启用，不能把该开关当成通用必要项。校验禁止输出渲染后的密码。

## 可重复验证

### 日志

- 对已授权的真实健康端点发起无副作用请求，附带唯一的非敏感标记；选择确定会写入应用日志的入口。不要把密钥当标记，也不要用故意制造业务错误作为默认测试。
- 经 Grafana 数据源或 Loki 受保护查询路径检索该标记，确认服务器、项目、服务标签正确。只回报命中数量和非敏感标签，避免把整段生产日志复制到报告。
- 若应用入口不输出日志，可用临时测试容器验证采集器；这只能称为采集通道验证，不能证明目标业务日志已接入。临时容器清理不应影响业务数据。
- 用实际标签替换下面的示例，不假定项目和服务名：

```logql
{node="app-server-1", compose_service="backend"}
```

### 指标

- 用中心查询接口确认指标实际有样本、时间戳在采集启动之后，并具有预期服务器标签。核对至少一个可比较数值，例如主机总内存。
- 仪表盘表达式必须使用实际指标名和标签，不能仅创建面板就宣称可用。CPU 的 rate 查询需等待足够样本；磁盘 I/O 不等于剩余容量，父设备与分区也不应无区别求和。
- 容器挂载宿主机 proc/sys 后仍需确认网络与文件系统指标来源；拿不到可信数据时明确不展示或说明限制。
- 请求量、错误率、延迟依赖应用埋点或 exporter，应单独验证。不把“Prometheus 启动”当作这些指标已存在。

### 稳定性与回退

- 确认业务容器没有因接入而重启；检查采集器资源、重启次数和发送错误。
- 排查按“源是否输出 → 是否采集 → 是否写入 → 查询范围/标签/时间”推进，避免数据未出现时直接重装平台。
- 仅在需要且已授权时测试中断后的缓冲恢复；不为测试而关闭共享中心服务。有限重试仍失败时报告明确阻塞，不无限循环。
- 回退优先恢复采集器配置或停止本次新增采集器；不删除中心日志、业务容器或数据卷。

## 证据分级

配置解析、采集器校验与 mock 测试属于本地/配置证据。源容器生成新日志、跨机写入、中心再次查询到标记才构成真实日志链路证据。未有凭据或公网不通时，报告已完成部分和阻塞点，不标记为完整接入成功。
