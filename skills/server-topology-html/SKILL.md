# Server Topology HTML

## Overview

先按仓库 `AGENTS.md` 读取必要规范，再建**关系模型**，最后画图。图上的每条线都必须能回答三个问题：谁连谁、方向是什么、源 IP 是谁。

产出一份 `/tmp/server-topology-<date>.html`：单文件、零外部依赖、可直接打开。页面固定包含六块：

1. 页头：数据来源、时点、真实 IP 警告；
2. 统计条：台数、在线入口数、跨机关系数、停用/空机数；
3. 筛选工具条：全部 / 生产 / Staging / 停用空机；
4. SVG 总览：5–6 个业务簇，簇内是同机部署，簇间才画箭头；
5. 逐台清单表；
6. 跨机关系卡片 + 风险说明。

## Hard Boundaries

- **只读**：不改远端配置、不重启服务、不动防火墙。核对网络只跑查询命令。
- 默认写 `/tmp`，不写进仓库；页内含真实 IP 时必须在页头加"仅本机临时查看"警告。
- 不把私钥、密码、Token、API key 写进 HTML，也不要打印到对话里。
- 不自动执行 `git add` / `commit` / `push`。
- 清单里没有的 DNS、地域、外部依赖，标"未确认 / 需另查"，不要补全猜测。
- 停用或空机不要混进生产簇；它们会让人误判爆炸半径。

## Workflow

### 1. 读事实

按顺序读，不要只 grep 片段——关系往往藏在 `notes` 里：

- `config/private/servers.toml`：**全文**，逐台的 name / region / 公网与私网 IP / applications / notes / verified_at。
- 涉及入口与算力分离时：`docs/guides/swarm-production.md`。
- `config/private/services.toml`：外部数据库、缓存、对象存储；为空就明确写"外部依赖未登记"。
- 需要时看 `config/private/*.snapshot.json`，但以 toml 的摘要为准。
- 记录数据时点：`updated_at` 与各应用 `verified_at` 可能不同，页脚要写清。

### 2. 建关系模型（先表格，后画图）

在纸上先列这张表，再动 SVG：

| 关系 | 画法 | 箭头方向 | 线上标签 |
|---|---|---|---|
| 域名 → 入口 | 域名 chip → 主机 | 单向 | 域名 / HTTPS |
| overlay 入站 | 入口 → 计算（实线） | 请求方向 | overlay 名称 |
| 隧道出向 | 计算 → 入口（虚线） | 流量方向 | WireGuard / 隧道 |
| NAT 出口 | **入口** → 外部依赖（虚线） | 源 IP 方向 | 出口经谁 NAT |
| 历史迁移 | 旧机 → 新机（灰虚线） | 迁移方向 | 已迁移 / 已停用 |
| 同机多业务 | 不画线 | — | "同机"徽标 |

六条硬规则：

1. **按业务簇分组，不按地域。** 同地域但无依赖的两台机器不该挨在一起；有跨机链路的才是一个簇。
2. **只画跨机关系。** 一台机器上的 traefik、app、db 用方框并列即可，不要画内部箭头。
3. **出口归属优先于应用归属。** 应用跑在 A、NAT 在 B 时，外部依赖（RDS / Redis / OSS）必须画在 **B → 外部**；A → B 只画隧道。否则读者会以为外部看到的是 A 的 IP。这是最容易画错、也最值得在图上写死的一条。
4. **入站与出向分成两条平行反向箭头**，不要用一条双向箭头；双向箭头看不出请求从哪进、流量从哪出。
5. **停用/空机单独一栏**，用灰虚线，不与在线节点共用实线边框。
6. **同机双业务要显式标注**（例如"与 ① 的 COMPUTE 是同一台"），否则会被当成两个独立故障域。

### 3. 选簇

一般 5–6 个，按重要性从左到右、从上到下：

1. 生产主链路（入口 / 算力分离、NAT 出口）；
2. 共享基础设施（一台机器扛多个服务）；
3. 独立业务机；
4. staging（几套互不相干的 Dokploy 可以并排）；
5. 停用 / 空机；
6. 其他（纯外部依赖、DNS 关系）。

超过 6 个就合并同类项；图不是清单，清单在表格里。

### 4. 版面配方

- 画布 `viewBox="0 40 1280 744"`；两行三列，行高 300，行间距 24。
- 行内宽度：620 + 18 + 300 + 18 + 276 = 1232；第二行按同样总宽分配。
- 每个面板：外框 `rx=14`，顶部 4px 角色色条；标题 13.5–14px，副标题 10.5px。
- 节点框：主机标题用 mono 12–12.5px；正文最小 **9px**，再小就删字，不要缩字号。
- 颜色语义固定：蓝=入口/网关，橙=计算节点，青=应用主机，灰虚线=停用/空机，红虚线=风险链路。图例只放一份，放在 SVG 底部，不要再在 HTML 里重复一行。
- 每台主机的 `<g>` 里加 `<title>`，用原生 tooltip 放备注；不引外部库。
- 统计条里的"跨机关系数"必须等于图上箭头条数；改图后回头数一遍。

推荐坐标（可直接抄）：

```
面板 A: x=24  y=64  w=620 h=300     面板 B: x=662 y=64  w=300 h=300
面板 C: x=980 y=64  w=276 h=300     面板 D: x=24  y=388 w=400 h=300
面板 E: x=442 y=388 w=470 h=300     面板 F: x=930 y=388 w=326 h=300
图例:   y=708                        页脚: y=756
```

面板 A 的内部顺序固定为：`公网用户 → 入口 → 计算`，出口依赖放在**入口正下方**；计算回入口的隧道箭头放在两条主机之间，标签贴线。

### 5. 写页面

- 页头三行：eyebrow、标题、来源与口径；下面一行真实 IP 警告。
- 统计条四项，数字要和清单对得上。
- 筛选按钮的 `data-filter` 与面板 `data-group` 对应；JS 只做一件事：给不匹配的面板加 `.dim`（opacity .1）。
- 表格列：服务器 / 地域 / 角色 / 承载与域名 / 与其他机器的关系 / 状态。
- 关系卡片每张只讲一条链路，标题写 `A → B：做什么`，正文写约束和风险。
- "值得注意"独立成块，放业务风险，不要塞进图里。
- 页脚写临时路径、数据时点、"未做实时探测"。

### 6. 渲染校验

macOS 用 Edge headless 截图，必须真的看一眼，不要只凭坐标自信：

```bash
EDGE="/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge"
"$EDGE" --headless --disable-gpu --screenshot=/tmp/topo.png \
  --window-size=1400,2500 --hide-scrollbars file:///tmp/server-topology-<date>.html
# 分段裁剪，逐段看
sips --cropOffset 900 0 -c 800 1400 /tmp/topo.png --out /tmp/topo-mid.png
```

没有 Edge 就找 Chrome / Chromium；都没有就至少用 `--dump-dom` 确认 JS 没报错。

**四看**：

1. 顶部是否多出一段空白（`viewBox` 从 y=40 开始，别从 0）；
2. 文字是否溢出面板或压在 chip 上（9px 中文约 9px/字，先估算再画）；
3. 图例是否重复（SVG 一份 + HTML 一份是高频错误）；
4. 箭头是否指向正确的源/目的（尤其 NAT 出口）。

### 7. 交付

`open` 页面，回报：文件路径、图里分了几个簇、最关键的两三条关系、以及任何"清单没写清"的待确认项。

## 涉及隧道 / NAT 时：先核对再画

不要只根据 `notes` 画出口。只读核对两台机器：

```bash
# 入口侧
wg show; ip -4 addr show wg0; ip rule; ip route show table 100
iptables -t nat -S POSTROUTING | grep -E 'MASQUERADE|10\\.99'
# 计算侧
wg show; ip route get 1.1.1.1          # 主机默认路由不能被隧道劫持
iptables -t mangle -L PREROUTING -v -n | grep MARK   # 看计数器是否命中
```

再做**两层出口验证**，缺一不可：

```bash
docker exec <app-container> curl -s https://ifconfig.me   # 应为入口公网 IP
curl -s https://ifconfig.me                                # 应仍为计算节点自己
```

如果结果和清单/图不一致，以实测为准，先修图，再说明差异；不要为了保持图好看而改结论。用户问"到底是 A 还是 B"时，按正确性 bug 处理：核对、改图、给出一句话数据流。

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| RDS 线画在计算节点下 | 误以为计算节点直连、白名单是它 | 画在 NAT 节点下，标签"出口经 X NAT" |
| 入站/出向合并成双向箭头 | 看不出请求从哪进 | 两条平行反向箭头 |
| 停用节点留在生产簇 | 高估故障域 | 单独一栏、灰虚线 |
| 同机双业务画成两个节点 | 误判为两个故障域 | 合并 + "同机"徽标 |
| 图例写两遍 | 页面显脏 | 只保留 SVG 内一份 |
| 9px 文字压到隔壁 chip | 不可读 | 拆行或删字，不缩字号 |
| 统计说 6 条关系、图里 5 条 | 失去可信度 | 改完图重新数 |
| 清单没有 DNS 就写死解析 | 把猜测当事实 | 标"需另查" |

## 模板

复制 `assets/topology-template.html`，替换 `&lt;...&gt;` 占位符：

- `&lt;ENTRY_IP&gt;` / `&lt;COMPUTE_IP&gt;`：入口与计算节点；
- `&lt;PUBLIC_IP&gt;` / `&lt;PRIVATE_IP&gt;`：共享主机；
- `&lt;DOMAIN&gt;` / `&lt;APP_NAME&gt;`：域名与应用；
- `&lt;DATE&gt;`：数据时点。

模板已包含：设计令牌、三列栅格、面板 A 的正确箭头画法、筛选 JS、SVG 图例、表格与关系卡片骨架。第二行面板的位置在注释里，按需复制。
